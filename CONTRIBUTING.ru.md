# Как помочь проекту Tusche

[English](CONTRIBUTING.md) · **Русский**

Спасибо за интерес! Tusche сейчас на **этапе 0 — спецификация**, поэтому больше всего пользы принесут:

1. **Ревью спецификаций** в [`docs/ru`](docs/ru): нашли пробел или ошибку — откройте issue.
2. **Тестовые файлы `.pen`**, которыми вы вправе делиться. Они станут эталонными файлами для тестов круговой конвертации и рендера.
3. **Исправления в OpenPencil**, от которых мы зависим. Список — в разделе «Найденные риски» в [02-research](docs/ru/02-research.md).

## Основные правила

- **«Чистая комната».** Поддержку `.pen` пишем только по публичной документации (<https://docs.pencil.dev/for-developers/the-pen-format>) и наблюдениям за самими файлами. Код, бинарники, тексты скиллов, картинки и другие ассеты pen.dev не копируем, pen.dev не декомпилируем.
- **Документация на двух языках.** У каждого файла в `docs/en` есть пара с тем же именем в `docs/ru`. Обновляйте обе версии в одном PR или заводите issue с меткой `translation`.
- **Решения оформляем как ADR.** Если меняется архитектура, формат или публичный API, нужен ADR в `docs/adr/en` и `docs/adr/ru`.
- **Conventional commits:** `feat:`, `fix:`, `docs:`, `chore:` и т. д.

## Разработка (с фазы 1)

```bash
bun install
bun run check   # типы, линтер, тесты
```

Нужен Bun ≥ 1.3. Опубликованные пакеты можно запускать и на Node ≥ 22.
