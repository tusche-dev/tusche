# 05 · Формат `.pen` — спецификация реализации в Tusche

`.pen` — JSON-формат документов, который High Agency придумала для pen.dev. Нормативный источник — их публичная схема: <https://docs.pencil.dev/for-developers/the-pen-format>. Здесь своими словами описано, **как Tusche читает, проверяет, редактирует и записывает этот формат**, и что мы увидели в реальных файлах. Если наша спецификация расходится с upstream, прав upstream — заведите issue.

Целевая версия: **2.21**. Чтение поддерживается для **2.x** (встречались 2.6, 2.17, 2.18, 2.20, 2.21).

## 1. Файл

- JSON в UTF-8. Upstream допускает комментарии; Tusche читает JSONC, а **пишет обычный JSON** без комментариев.
- Файл лежит в папке проекта. Ассеты (картинки, шейдеры `.glsl`, скрипты `.js`, подключённые `.pen`-библиотеки) указываются **путями относительно файла**.
- Переводы строк встречаются оба варианта: файлы, созданные приложением, бывают с CRLF. Tusche сохраняет вариант исходного файла, новые пишет с LF (см. раздел 11).

## 2. Корень документа

| Поле | Тип | Примечания |
|---|---|---|
| `version` | string | Например, `"2.21"`. По нему выбираются миграции. |
| `children` | Node[] | Ноды верхнего уровня: экраны, компоненты, контейнеры |
| `variables` | map имя → определение | Типизированы: `boolean`, `color`, `number`, `string` |
| `themes` | map ось → values[] | Например, `{"mode": ["light","dark"]}`. Первое значение — значение по умолчанию. |
| `imports` | map алиас → относительный путь | Другие `.pen`-файлы, подключённые как библиотеки |

Любой другой ключ верхнего уровня сохраняется как есть.

## 3. Общие поля нод

У каждой ноды есть `type` и `id`. Id — короткие случайные строки, и в них **не должно быть `/`**: этот символ зарезервирован для путей внутрь инстансов компонентов (`instanceId/childId/...`).

| Поле | Значение |
|---|---|
| `name` | Человекочитаемое имя слоя |
| `x`, `y` | Позиция относительно левого верхнего угла родителя. Игнорируется, если у родителя flex-layout, кроме случая `layoutPosition: "absolute"` |
| `rotation` | Градусы против часовой стрелки вокруг левого верхнего угла |
| `opacity`, `enabled` | `enabled: false` скрывает ноду; этим же способом «удаляют» ноды внутри инстансов |
| `flipX`, `flipY` | Отражение |
| `reusable` | `true` превращает ноду в компонент |
| `theme` | Выбирает значения темы для поддерева, например `{"mode":"dark"}` |
| `layoutPosition` | `"auto"` или `"absolute"` |
| `context`, `metadata` | Произвольные аннотации; сохраняются |

**Ссылки на значения:** почти любое скалярное значение может быть ссылкой на переменную — строкой, начинающейся с `$` (`"$primary"`, `"$space-4"`).

## 4. Типы нод

| Тип | Дети | Главное |
|---|---|---|
| `frame` | да | Контейнер: необязательный flex-layout, заливки, обводки, скругление, `clip`, `placeholder`, `slot` |
| `group` | да | Простая группировка, только эффекты |
| `rectangle` | — | Заливки, обводки, `cornerRadius` (одно значение или четыре) |
| `ellipse` | — | `innerRadius` (кольцо), `startAngle`, `sweepAngle` (дуги, бублики) |
| `polygon` | — | `polygonCount`, `cornerRadius` |
| `path` | — | SVG-`geometry`, `viewBox` `[x,y,w,h]`, растянутый на бокс ноды, `fillRule` |
| `text` | — | `content`, стиль текста, `textGrowth` |
| `icon` | — | `library` + имя `icon`, необязательный `weight`; масштабируется по боксу |
| `ref` | — | Инстанс переиспользуемой ноды: `ref` (id цели) + переопределения `descendants` + переопределения верхнего уровня |
| `note`, `prompt`, `context` | — | Аннотации на холсте; у `prompt` есть необязательный `model` |
| `script` | — | `scriptUri` (JS-файл) + `inputs`; генерирует детей во время выполнения |
| `browser` | — | Живая веб-страница: `url`, `deviceId`, `zoom`, `scrollX/Y` |

В старых файлах может встретиться `icon_font` (мы видели его в импортёре OpenPencil). Он мигрирует в `icon`.

## 5. Размеры и layout

- `width` / `height`: число, переменная или строка с **режимом размера**: `fit_content` (обнять детей; нужен layout на самой ноде) или `fill_container` (растянуться по layout родителя). Запасное значение указывается в скобках: `"fit_content(320)"`.
- **Не поддерживаются:** проценты, `calc`, единицы вьюпорта, отступы-margin, `alignItems: baseline|stretch`, перенос (wrap) во flex.
- Layout фрейма: `layout` бывает `none`, `horizontal` (**у фреймов это значение по умолчанию**) или `vertical`. Плюс `gap`, `padding` (1, 2 или 4 значения), `justifyContent` (`start|center|end|space_between|space_around`), `alignItems` (`start|center|end`), `layoutIncludeStroke`.
- По умолчанию фрейм имеет размер `fit_content` по обеим осям, `clip` по умолчанию `false`.
- Если у родителя `fit_content`, а все его дети по этой оси — `fill_container`, получается циклическая зависимость. Tusche берёт запасное значение и выдаёт предупреждение.

### Рост текста

| `textGrowth` | Ширина | Высота | Перенос строк |
|---|---|---|---|
| `auto` (по умолчанию) | по содержимому | по содержимому | никогда |
| `fixed-width` | обязательна (число или `fill_container`) | по содержимому | да |
| `fixed-width-height` | обязательна | обязательна | да; текст может вылезать |

У текста **нет заливки по умолчанию**, поэтому текст без `fill` невидим. Tusche выдаёт предупреждение.

## 6. Заливки, обводки, эффекты

**Fill** — одно значение или массив; слои рисуются снизу вверх:

| Вид | Поля |
|---|---|
| цвет | `"#RGB" | "#RRGGBB" | "#RRGGBBAA"`, переменная или `{type:"color", color, enabled, blendMode}` |
| `gradient` | `gradientType` (`linear|radial|angular`), `colors[{color, position}]`, `center`, `size`, `rotation`, `opacity` |
| `image` | `url` (относительный), `mode` (`cover|contain|stretch`), `transform` (аффинный кроп), `opacity` |
| `shader` | `url` на фрагментный шейдер GLSL ES 1.0, `uniforms` |
| `mesh_gradient` | `columns`, `rows`, `colors[]`, `points[]` с необязательными безье-ручками |

**Обводка:** `stroke` (заливки), `strokeWidth` (общая или по сторонам; без неё обводки нет), `strokeAlignment` (`inner|center|outer`, по умолчанию `center`), `strokeLinecap`, `strokeLinejoin`.

**Эффекты:** `blur`, `background_blur`, `shadow` (`inner|outer`, `offset`, `blur`, `color`, `blendMode`), `shader` (постобработка). Режимы наложения — привычные 18 названий в духе Figma.

## 7. Стиль текста

`fontFamily`, `fontSize`, `fontWeight` (строка), `fontStyle`, `letterSpacing`, `lineHeight` (**множитель** размера шрифта), `textAlign` (`left|center|right|justify`), `textAlignVertical` (`top|middle|bottom`), `underline`, `strikethrough`, `href`.

## 8. Компоненты и инстансы

- Любая нода с `reusable: true` — компонент.
- `{"type":"ref","ref":"<componentId>", ...overrides}` — инстанс. Ключи верхнего уровня переопределяют корень.
- `descendants` сопоставляет **путь из id внутри компонента** (`"childId"` или `"nestedInstance/childId"`) одному из вариантов:
  - объект **без** `type` — переопределения свойств, которые вливаются в этого потомка;
  - объект **с** `type` — потомок **заменяется** этим новым поддеревом.
- Потомка внутри инстанса «удаляют» через `enabled: false`.
- `slot: ["componentId", ...]` на фрейме помечает его как слот для вставки и перечисляет рекомендуемые компоненты.
- Копия переиспользуемой ноды создаёт `ref`, а не глубокую копию.

## 9. Переменные и темы

```json
{
  "themes": { "mode": ["light", "dark"] },
  "variables": {
    "bg": { "type": "color", "value": [
      { "value": "#FAFAF7", "theme": { "mode": "light" } },
      { "value": "#141414", "theme": { "mode": "dark" } }
    ] },
    "space-4": { "type": "number", "value": 16 }
  }
}
```

- Значение — простое или список записей `{value, theme}`. При разрешении побеждает **последняя** запись, тема которой совпадает с активной; если подходящей нет, берётся тема по умолчанию.
- Контекст темы наследуется вниз по дереву от ближайшей ноды с `theme`.
- Значения могут ссылаться на другие переменные.

## 10. Матрица совместимости: `.pen` → scene graph OpenPencil (через `pen-bridge`)

Статусы: ✅ прямое соответствие · 🟡 приближение · ⬜ только заглушка (в файле остаётся нетронутым)

Проекцию пишет `@tusche/pen-bridge` ([ADR-007](adr/007-pen-scene-projection.md)), импортёр `@open-pencil/pen` не используется. Наблюдения — по сверке с экспортом pen.dev 2026-10-20 (eval, `app.pen`, `website.pen`, `main.pen`; [02-research](02-research.md)).

| Возможность `.pen` | Во что превращается в scene graph | Статус | Наблюдения (этап 1.3) |
|---|---|---|---|
| frame / flex-layout / gap / padding / выравнивание | FRAME + auto layout (Yoga) | ✅ | Совпадает с pen.dev до пикселя. `gap` при `space_between` сохраняется (патч), `space_around` рисуется как `space_between` 🟡 |
| `fit_content` / `fill_container` / запасное значение | Режимы HUG / FILL | ✅ | Соседи `fill_container` делят место поровну и с разным padding (патч); запасное значение — вне layout и при циклическом размере |
| `clip` | clipsContent | ✅ | |
| group | GROUP | ✅ | Размер — по детям. В реальных файлах не встретилась |
| rectangle, ellipse (дуги, кольцо) | RECTANGLE, ELLIPSE (arcData) | ✅ | Углы против часовой → по часовой |
| polygon | POLYGON | ✅ | В реальных файлах не встретился |
| path + viewBox | VECTOR (с масштабированием) | ✅ | Без `viewBox` — точные границы геометрии |
| text + textGrowth | TEXT с режимами авторазмера | ✅ | `auto` никогда не переносится; высота строки округляется до пикселя; перенос — по целой ширине (патч) |
| icon | VECTOR из данных Iconify | ✅ | Офлайн-наборы lucide и phosphor, прочие — Iconify API с кэшем |
| ref + descendants | плоское разворачивание, id = pen-путь | ✅ | Без INSTANCE OpenPencil. Ленивость по корням: `app.pen` целиком — 44 тыс. нод сцены за 0,6 с |
| переменные + темы | конкретные значения по контексту темы | ✅ | Тема берётся по месту вставки инстанса, заливки состояний больше не пропадают |
| заливки цветом / градиентом / картинкой | Paints | ✅ | `cover` / `contain` / `stretch` → FILL / FIT / CROP; миграция `fill` → `cover` подтверждена рендером `website.pen`. `transform` картинки пока не применяется 🟡 |
| обводки: `stroke` (заливка или список) + `strokeWidth` | Strokes | ✅ | По умолчанию по центру; без `strokeWidth` не рисуется; у фрейма — поверх детей (служебная нода `…#stroke`) |
| mesh_gradient | линейный градиент | 🟡 | Цвета верхнего и нижнего ряда. В реальных файлах не встретился |
| shader fill / effect | заглушка | ⬜ | Шейдер-заливка без других заливок — серая плашка, поверх других — пропускается; эффект пропускается. Фаза 2: CanvasKit `RuntimeEffect` |
| shadow, blur, background blur | Effects | ✅ | Тени совпадают; pen.dev отводит под размытие при экспорте чуть больше полей |
| note / prompt / context | карточка-стикер | ⬜ | Подпись типа и текст |
| script | FRAME с пунктирной рамкой | ⬜ | Фаза 3: выполнять в песочнице QuickJS |
| browser | FRAME с пунктирной рамкой и URL | ⬜ | Фаза 2: настоящий webview поверх холста в десктопе |
| imports (библиотеки) | — | ⬜ | Фаза 3 |

### Уточнения семантики по сверке с pen.dev

В публичной схеме этого нет, в рендерах pen.dev — есть:

- `strokeAlignment` по умолчанию — `center`. Без `strokeWidth` обводка не рисуется.
- Обводка фрейма рисуется поверх его детей.
- `gap` при `justifyContent: space_between` — минимальный промежуток (как в CSS), а не ноль.
- Соседи с `fill_container` по главной оси получают равные доли независимо от своего padding.
- Высота строки — `round(lineHeight × fontSize)` на каждую строку.
- Текст с `textGrowth: auto` не переносится, даже если выходит за родителя.
- Ребёнок с `fill_container` по поперечной оси у `fit_content`-родителя растягивается до размера, который задали остальные дети.

## 11. Сериализация (как Tusche пишет файлы)

Главное правило — **сохранить стиль исходного файла**, чтобы git-диффы оставались минимальными и не было «пинг-понга» с pen.dev. Подробности и мотивация — в [ADR-006](adr/006-style-preserving-serialization.md).

1. Отступ, переводы строк (LF / CRLF) и наличие перевода строки в конце берутся из исходного файла. Новый файл пишется как у pen.dev: два пробела, LF, **без** перевода строки в конце, UTF-8 без BOM.
2. Порядок ключей существующих объектов сохраняется таким, каким был при чтении.
3. **Канонический порядок для новых нод:** `type`, `id`, `name`, `reusable`, `ref`, `x`, `y`, `width`, `height`, затем остальные известные ключи в порядке схемы, затем неизвестные, `descendants` и **`children` в самом конце**. Новый ключ у существующей ноды встаёт по этому порядку относительно соседей, а если опереться не на что — в конец перед `descendants` / `children`.
4. Порядок ключей нового корня: `version`, `themes`, `imports`, `variables`, `children`, затем неизвестные ключи.
5. **Значения по умолчанию Tusche сам не пишет**, но и не удаляет уже записанные (pen.dev их пишет, например `enabled: true` у градиентов).
6. Числа — как у `JSON.stringify`, без `-0`.
7. Если файл прочитан и ничего не менялось, он записывается байт в байт (требование N3).

## 12. Версии и миграции

- В `pen-format` хранится упорядоченный список миграций `2.x → 2.y` (от 2.6 до 2.21; в реальных файлах встречались 2.6, 2.17, 2.18, 2.20, 2.21). Миграции выполняются в памяти при открытии; файл записывается в новейшей версии **только при сохранении после правки**.
- Неизвестная **более новая** версия открывается на чтение и запись с предупреждением; неизвестные свойства сохраняются.
- У каждой миграции есть тесты на фикстурах, собранных из реальных файлов.

## 13. Уровни проверки

| Уровень | Пример | Поведение |
|---|---|---|
| Ошибка | `padding` на текстовой ноде; `width: "50%"`; id со `/` | `execute` бросает исключение, транзакция откатывается |
| Предупреждение | текст без заливки; потомок обрезан родителем; циклические размеры | Возвращается в ответе `execute` |
| Информация | явно указано значение по умолчанию; неизвестное свойство | Только диагностика, файл не меняется (ADR-006) |
