# ADR-007 · Проекция `.pen` в scene graph: плоские инстансы, id — pen-путь

- **Статус:** Принято
- **Дата:** 2026-10-20
- **Уточняет:** [ADR-001](001-build-on-openpencil.md), [ADR-002](002-pen-native-format.md), раздел 10 [05-pen-format](../05-pen-format.md)

## Контекст

`@tusche/pen-bridge` строит `SceneGraph` из `PenDocument`: на нём `@tusche/engine` считает раскладку, границы и рендер. ADR-002 разрешал переиспользовать импортёр `@open-pencil/pen`, но практические тесты ([02-research](../02-research.md)) показали, что для файлов 2.x он не годится:

- теряет все обводки (ждёт старую форму `stroke: {fill, thickness}`) и падает на `stroke`-массиве;
- не знает `group`, `polygon`, градиенты, картинки, дуги эллипса, blur; иконки рисует текстовым глифом;
- переменные отдаёт в коллекцию OpenPencil с одной активной темой на весь документ: у нод с собственной `theme` заливки пропадают или берутся из чужой темы;
- переопределения `descendants` ищет эвристикой по имени и типу, глубокие ключи `a/b` не разбирает.

Отдельно надо было решить, как сопоставлять ноды сцены с нодами `.pen`. Внутри инстанса у ноды нет своего id в файле — только путь `instanceId/childId[/…]` (раздел 4 спецификации).

## Решение

1. **Своя проекция.** Импортёр `@open-pencil/pen` не используется; из него берутся только идеи. Мост пишет ноды через публичный API `@open-pencil/scene-graph` (`createNodeWithId`, `parseSVGPath`, хелперы раскладки и градиентов).
2. **Плоское разворачивание инстансов.** `ref` разворачивается мостом в обычные ноды (FRAME, TEXT, …). Механизм COMPONENT / INSTANCE OpenPencil не используется: синхронизация инстансов — его логика, а источник истины у нас — дерево `.pen`. Разрешение путей и переопределений — функции `@tusche/pen-format` (`resolveInInstance`, `effectiveNode`), те же, что у валидатора и `execute`.
3. **id ноды сцены = pen-путь.** Обычная нода получает свой id, нода внутри инстанса — путь `instanceId/childId/…`. Обратного словаря не нужно: границы и проблемы, найденные engine, сразу адресуются тем же путём, что принимает API `execute`. Вспомогательные ноды проекции (векторы иконки, подписи заглушек) получают id с суффиксом `#` (`icon#0`), который не может встретиться в `.pen`.
4. **Переменные и темы разрешаются в мосте** до конкретных значений, с контекстом темы, который наследуется по дереву, включая инстансы (`resolveValue` из `@tusche/pen-format`). Имена переменных сохраняются в `pluginData` ноды (ключ `tusche`), чтобы в фазе 2 редактор мог их показать.
5. **Ленивость по корням.** Проецируются только запрошенные ноды верхнего уровня (и компоненты, на которые они ссылаются, — только как источник данных, без нод сцены). Пересборка идёт по корню целиком; это зерно инкрементальной проекции из [04-architecture](../04-architecture.md).
6. **Ввод-вывод — через провайдеры.** Мост не трогает файловую систему и сеть: байты картинок и векторы иконок приходят через `loadAsset` и `IconProvider`. По умолчанию иконки берутся из офлайн-наборов Iconify (`@iconify-json/lucide`, `@iconify-json/ph`).
7. **Неподдерживаемое видно.** shader-заливка → нейтральная серая заливка, `script` / `browser` → рамка с подписью, `note` / `prompt` / `context` → карточка-стикер. Каждая заглушка даёт предупреждение проекции; `PenDocument` не меняется.

## Последствия

- ➕ Обводки, темы на уровне нод, глубокие переопределения и замены работают так же, как в валидаторе: одна реализация семантики `.pen`.
- ➕ Путь из ошибки или `bounds` можно сразу передать в `Update` — без перевода id.
- ➕ Ленивость по корням ограничивает раздувание графа (в `app.pen` 2,5 тыс. pen-нод → ~39 тыс. нод сцены при полном развороте).
- ➖ Редактор фазы 2 не получает «живых» инстансов OpenPencil: правка компонента — правка `.pen` и пересборка затронутых корней. Это соответствует ADR-002.
- ➖ Переопределение темы на лету (переключить тему без пересборки) недоступно: значения уже подставлены. Для фазы 1 этого достаточно.
- ➖ Улучшения моста не идут upstream автоматически: полезные исправления импортёра (`stroke`) отправляем отдельными PR в 1.8.
