# ADR-011 · Живой предпросмотр: слежение за файлом, раскладка на сервере, WebGL в браузере

- **Статус:** Принято
- **Дата:** 2026-10-23
- **Уточняет:** [04-architecture](../04-architecture.md) §«Живой предпросмотр», [ADR-009](009-mcp-sessions.md) §5

## Контекст

Этап 1.7: `tusche preview file.pen` показывает в браузере, что делает агент. В 04 предполагалось, что страница подписывается по WebSocket на события изменений от MCP-процесса и рисует документ холстом `@open-pencil/core` (WebGL). Из этого вытекают два вопроса.

1. **Откуда preview узнаёт об изменениях.** MCP-сервер запускает клиент агента по stdio, а `tusche preview` — отдельная команда пользователя. Чтобы получать события `onChange` (ADR-009), MCP-процессу пришлось бы поднимать HTTP-сервер, и preview жил бы только вместе с сессией агента.
2. **Где раскладывать документ.** Раскладка `.pen` держится на коде `@tusche/engine`, которому нужен Node: поправки раскладки (`resetStaleStretch`, измеритель текста), шрифты с дисковым кэшем и подмножествами, иконки Iconify, локальные изображения. `pen-bridge` тянет `node:module` ради офлайн-иконок, а `io/formats/raster` после нашего патча импортирует `node:url`. Перенос всего этого в браузер — заметная работа, и раскладка на странице могла бы разойтись со скриншотами агента.

Спайк показал, что разложенный scene graph — это обычные данные: `Map` нод, типизированные массивы и `Map` в `instanceOverrides`. После круга через JSON и восстановления в новом `SceneGraph` рендер всех 7 корней реального файла совпал со `scene.export` пиксель в пиксель. Модули OpenPencil для рисования (`canvas`, `canvaskit`, `text`, `scene-graph`) собираются под браузер, Node-импорты у них только в недостижимых ветках.

## Решение

1. **Источник изменений — сам файл.** `tusche preview` читает `.pen` и следит за ним через `fs.watch` на папку файла, а не на сам файл: атомарная запись через rename ломает watch на файл. Дебаунс 100 мс, повторное содержимое отсекается хэшем. Так подхватываются MCP (запись через 300 мс после коммита), CLI, pen.dev, редактор и git. MCP не меняется; `onChange` остаётся заделом для фазы 2.
2. **Раскладка на сервере, рисование в браузере.** Сервер раскладывает документ тем же `Scene.layout`, что и для агента, и отправляет готовые ноды scene graph по корням (`snapshotRoot`). Страница кладёт все корни на одну страницу своего `SceneGraph` и рисует их `SkiaRenderer` на WebGL-поверхности. Hit-test — `hitTestDeep` графа; id ноды сцены — pen-путь (ADR-007). Служебные ноды проекции (`path#stroke` и т. п.) отдают id своей ноды, оверлей обводки в hit-test не участвует.
3. **Только изменённые корни.** Перечитанный документ сравнивается с прошлым: равные по JSON корни и данные документа заменяются прежними объектами, после чего `rootsBetween` из `@tusche/exec` находит корни для повторного показа, включая инстансы изменённых компонентов. Новой странице уходит весь документ, дальше — только изменённые корни и порядок. WebSocket сжимается (`perMessageDeflate`).
4. **Шрифты — те же файлы, что у движка.** Сервер перечисляет все загруженные файлы шрифтов (`loadedFontFiles`, id — хэш байтов) и отдаёт их по `/fonts/<id>`. Страница регистрирует их через `fontManager.markLoaded` в том же порядке: дополнительные файлы грани идут раньше основного. Встроенный Inter и `canvaskit.wasm` сервер берёт из пакетов OpenPencil (`previewFile`).
5. **Где лежит код.** Снапшот и кодек сообщений — в `@tusche/engine`. Браузерный холст — отдельный экспорт `@tusche/engine/preview` без `node:*`, так что `@open-pencil/core` по-прежнему импортирует только engine. Сервер и страница — пакет `@tusche/preview` (`packages/preview`) вместо `apps/preview`: от него зависит CLI, и в 1.9 он публикуется в npm. Страница собирается `Bun.build` при старте сервера, в памяти.
6. **Ошибки.** Нечитаемый файл, битый JSON или удалённый файл не стирают показанное: странице уходит сообщение `error`, последнее хорошее состояние остаётся.

## Последствия

- ➕ Пиксели на странице совпадают со скриншотами агента и `tusche render`, зум остаётся чётким, а поправки раскладки не дублируются в браузере.
- ➕ Preview не зависит от сессии агента и работает с любым источником правок.
- ➕ `PreviewScene` не зависит от DOM, поэтому восстановление сцены проверяется тестом без браузера через headless-рендер.
- ➖ Видны только сохранённые правки: MCP пишет через 300 мс после коммита.
- ➖ Корень весит сотни килобайт JSON: полная сцена файла из 7 экранов — несколько мегабайт до сжатия. Для локального сервера это приемлемо.
- ➖ Список загруженных шрифтов берётся из закрытых полей `fontManager`. При обновлении OpenPencil это место нужно проверить; если появится публичный метод, перейти на него.
- ➖ Страница только смотрит: правки руками — фаза 2.
