# ADR-001 · Строим поверх пакетов OpenPencil: без форка и без своего движка

- **Статус:** Принято
- **Дата:** 2026-10-20

## Контекст

Холсту для дизайна нужны:

- рендерер: векторные пути, шейпинг текста, эффекты, картинки;
- движок layout: flex, режимы hug/fill;
- scene graph с компонентами и переменными;
- hit testing, экспорт и UI редактора.

Если писать всё это с нуля, пройдут месяцы, прежде чем можно будет вообще начать агентный опыт — то, чем мы на самом деле отличаемся.

Рассмотренные варианты:

1. **Свой движок с нуля** (например, Rust + vello + taffy или TS + CanvasKit). Полный контроль, огромный объём работы.
2. **Форк OpenPencil.** Полная свобода в UI и коде, но придётся бесконечно сливаться с быстро меняющимся upstream: около 3000 коммитов за 8 месяцев.
3. **Зависеть от опубликованных npm-пакетов OpenPencil** и строить свой слой поверх них.
4. **Строить на ZSeven-W/openpencil** (ядро на Rust). У него свой формат `.op`, а `.pen`-киты он только импортирует. Взять его — значит принять его формат и архитектуру.

Факты (см. [02-research](../02-research.md)):

- `@open-pencil/core` работает headless на Windows; есть один баг с путём, он исправим.
- Реальные дизайны в `.pen` он рендерит с хорошей точностью.
- Редактор, layout, растр, линтер и инструменты доступны как subpath-экспорты.
- Лицензия MIT.
- Для будущего десктопного приложения уже есть Vue SDK.

## Решение

Вариант 3. Tusche зависит от зафиксированных версий пакетов `@open-pencil/*`.

- **Импортирует `@open-pencil/core` только `@tusche/engine`.** `@tusche/pen-bridge` импортирует `@open-pencil/scene-graph`.
- Всё остальное работает через наши собственные интерфейсы.
- Нужные нам исправления в OpenPencil **сначала отправляем PR в upstream**. Локальные патчи (`bun patch`) держим только до их слияния.

## Последствия

- ➕ До MVP недели, а не месяцы. Бесплатно получаем рендерер и layout уровня Figma, импорт `.fig` и множество форматов экспорта.
- ➕ Улучшения идут в обе стороны, отношения с upstream остаются хорошими.
- ➖ Зависим от API версии 0.x с bus factor около 1. Как снижаем риск:
  - фиксируем точные версии;
  - держим границу через адаптер;
  - покрываем эту границу контрактными тестами;
  - если upstream заглохнет, можем перенести пакет к себе в репозиторий — MIT это позволяет.
- ➖ Совпадение рендера с pen.dev не гарантировано. Мы принимаем «точно», а не «идентично».
- Форк остаётся возможным позже, если пути с upstream разойдутся. Граница через адаптер ограничит цену такого шага.
