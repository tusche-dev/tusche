# 06 · Agent API — MCP tools and `execute`

**English** · [Русский](../ru/06-agent-api.md)

Design goal: an agent that already knows pen.dev's `execute` vocabulary should be productive in Tusche immediately. **Function names and semantics are deliberately compatible.** The implementation, documentation and skill are our own.

## 1. MCP tools

Transport: stdio (phase 1). Server name: `tusche`. Every tool takes an optional `filePath`; if it is omitted, the active document is used.

| Tool | Input | Output |
|---|---|---|
| `get_app_state` | — | Active document, open documents, versions, selection (phase 2), unsaved state, conflicts, a short "how to start" hint |
| `read_skill` | `path?` | `SKILL.md`, or a referenced guide (`execute.md`, `guide/web-app.md`, …) |
| `get_style` | `name?`, `params?` | No args: the list of archetypes. With `name`: a style or its required params |
| `open_document` | `filePath`, `create?` | Opens or creates a `.pen`; returns a summary (top-level frames, components, variables) |
| `save_document` | `filePath?` | Force a save (saves are otherwise automatic after each successful `execute`) |
| `execute` | `filePath`, `input` **or** `editId` + `edits[]` | See below |
| `render` | `nodeIds[]`, `scale?` | PNG images. For humans and agents that want a picture without running JS |
| `lint` (could) | `nodeId?` | OpenPencil lint findings mapped to pen ids |

There is **no** `browser` or `Generate` in phase 1 (see the roadmap).

## 2. `execute`

### Request

```jsonc
// first attempt
{ "filePath": "/abs/design/app.pen", "input": "<javascript snippet>" }

// fix after a failure — never resend the whole snippet
{ "filePath": "/abs/design/app.pen", "editId": "e7", "edits": [
  { "find": "fontSize:64", "replace": "fontSize:56" },
  { "find": "Inter", "replace": "Manrope", "all": true }
]}
```

- `edits` apply in order to the stored failed snippet; each `find` must match exactly once unless `all: true`. The patched snippet runs from scratch.
- If it fails again, the agent keeps patching under the same `editId`.

### Response

Plain text, compact, in this order:

```
ok · 3 inserted · 1 updated · 0 deleted · 142 ms
names:
  Hero=Kp2xQ  Headline=a9Fz1  Subhead=Lm3Qe
print:
  Kp2xQ Hero 1440 640
warnings:
  [clipped] "Card Grid" (Rt5Yu) is partially clipped by "Hero" (Kp2xQ)
```

…plus one `image` content block per `TakeScreenshot` id. On failure:

```
error · rolled back · editId=e7
  TypeError: Insert(): "padding" is not allowed on node type "text"
  at line 4:  Insert(card,{type:"text",content:"Hi",padding:12})
hint: wrap the text in a frame and put padding on the frame
```

### Execution model

- Each call is a **transaction**: all changes commit together, or none do.
- Each call gets a fresh scope. **Globals persist** across calls on the same document when assigned without `const` / `let` / `var` (`heroId = Insert(...)`). Only JSON-serialisable values persist.
- Limits: 10 s CPU, 256 MB memory, 2,000 operations per call, 6 screenshots per call.
- `document` is a predefined constant: the root id.
- Ids are always generated by Tusche; an `id` in input data is ignored with a warning.

### API reference

```ts
declare const document: string

// ── mutations ────────────────────────────────────────────────
Insert(parent: string, node: PenNode): string          // appends; returns new id
Copy(path: string, parent: string, overrides?: Partial<PenNode> & { descendants?: Descendants }): string
Update(path: string, props: Partial<PenNode>): void    // cannot change id/type/ref/children
Replace(path: string, node: PenNode): string           // whole node, incl. inside instances
Move(path: string, parent?: string, index?: number): void
Delete(path: string): void                             // inside instances: use Update(path,{enabled:false})
SetVariables(vars: Record<string, VariableDef>, replace?: boolean): void

// ── reads ────────────────────────────────────────────────────
Get(path: string, opts?: GetOptions): PenNode
Get<T>(path: string, visit: Visit<T>, opts?: GetOptions): T[]
Get<T>(visit: Visit<T>, opts?: GetOptions): T[]
GetVariables(): { variables: Record<string, VariableDef>; themes?: Record<string, string[]> }
FindEmptySpace(q: { width: number; height: number; direction?: 'top'|'right'|'bottom'|'left'; padding?: number; nodeId?: string }): { x: number; y: number; parentId?: string }

// ── output ───────────────────────────────────────────────────
Print(...values: unknown[]): void
TakeScreenshot(nodeIds: string[], opts?: { scale?: number }): void
Export(nodeIds: string[], format: 'png'|'jpeg'|'webp'|'pdf'|'svg'|'html-tailwind', outPath: string, opts?: ExportOptions): void

interface GetOptions { depth?: number; resolveVariables?: boolean; resolveInstances?: boolean; includePathGeometry?: boolean }
type Visit<T> = (node: PenNode, ctx: Ctx) => T | undefined
interface Ctx {
  node: PenNode; parentCtx?: Ctx; depth: number; index: number
  bounds: { x: number; y: number; width: number; height: number }  // resolved, in parent space
  problems?: 'partially clipped' | 'fully clipped'
  skipChildren(): void
}
```

Semantics that matter:

- **Paths.** `path` is a node id, or `instanceId/childId[/…]` for nodes inside component instances. Never a node object.
- **`Get` reflects pending changes** in the same call: it flushes to the bridge and runs layout.
- **Visitors:** returning `undefined` collects nothing; any other value is collected. There is intentionally no visitor-less read of the whole document.
- **`Copy` of a reusable node returns a `ref`.** Descendant customisation goes in the `descendants` argument of the same `Copy`, because the copy's descendants get new ids.
- **`TakeScreenshot`** renders after all of the call's mutations are applied; images attach to the response. A failed call returns no screenshots.
- **`Export`** writes under the document's directory unless `TUSCHE_ROOT` allows more. Paths are returned in the response.

## 3. Warnings catalogue (phase 1)

| Code | Trigger |
|---|---|
| `clipped` | Node's resolved bounds exceed a clipping ancestor |
| `invisible-text` | Text node with no `fill` |
| `zero-size` | Frame resolves to 0 width or height |
| `circular-size` | `fit_content` parent with only `fill_container` children on that axis |
| `ignored-xy` | `x` / `y` set on a child of a flex parent |
| `unknown-font` | Font family not resolvable; a fallback is used |
| `id-ignored` | `id` provided in input |
| `unsupported-render` | Node or paint not renderable yet (shader, script, browser); kept in file |

## 4. `get_style` archetype format

```jsonc
{
  "name": "Quiet Editorial",
  "summary": "Serif display + grotesk body, generous whitespace, one accent",
  "params": { "accent": ["terracotta", "ink-blue", "olive"] },   // optional
  "fonts": { "display": "Fraunces", "body": "Inter" },
  "palette": { "bg": "#F7F4EE", "text": "#1B1A17", "muted": "#6B675F", "accent": "$param.accent" },
  "scale": { "type": [14, 16, 20, 28, 40, 64], "space": [4, 8, 12, 16, 24, 40, 64, 96], "radius": [0, 4, 8] },
  "imagery": "Warm natural-light photography; no 3D renders",
  "rules": ["Left-aligned headlines", "No drop shadows", "Max 2 font weights per screen"],
  "variables": { /* ready-to-pass SetVariables payload */ }
}
```

Archetypes are original to Tusche and live in `@tusche/styles` as JSON. Contributions are welcome.

## 5. Compatibility notes vs pen.dev

| Area | Tusche phase 1 |
|---|---|
| `execute` core vocabulary | Same names and semantics |
| `Generate` (AI / stock / SVG / background removal) | Not provided. The skill tells the agent to use its own tools, save files next to the `.pen`, and use image fills |
| `browser` tool | Not provided (phase 2) |
| `spawn_agents` / parallel agents | Not provided (phase 3, via the user's CLI sub-agents) |
| Extra | `render`, `open_document`, `save_document`, `lint`, `svg` export |
