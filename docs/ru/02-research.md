## 1. pen.dev (бывший Pencil)

### Компания и продукт

- Разработчик — High Agency, Inc. (CEO Tom Krcha), участник a16z speedrun. Запуск — январь 2026 года под именем *Pencil* (pencil.dev); в августе–сентябре 2026 переименован в *pen.dev*. К февралю 2026 года — около 100 000 пользователей.
- Распространение: десктоп-приложение (macOS, Windows, Linux), расширение для VS Code / Cursor (`highagency.pencildev`), CLI `@pen.dev/cli`, веб-импортёр.
- Код закрыт, EULA запрещает реверс-инжиниринг. Схема формата `.pen` опубликована открыто.
- Документация: <https://docs.pencil.dev> (она же docs.pen.dev). Цены: <https://pen.dev/pricing>. Условия: <https://pen.dev/terms-of-use>, <https://pen.dev/eula>.

### Технологии (по установленному приложению)

- **Оболочка.** Electron 44; редактор — веб-приложение (`out/editor/index.js`, около 7.6 МБ).
- **Рендер.** Собственный, это WebAssembly-модуль на ~9.5 МБ (`pencil-*.wasm`) плюс модули Emscripten. На сайте он назван «custom WebGL pipeline», сторонние разборы указывают на сборку на базе Skia/CanvasKit.
- **Песочница.** QuickJS, скомпилированный в WASM (`quickjs-wasi`). В ней выполняются сниппеты агента через `execute` и ноды `script`.
- **Встроенные агенты.** Claude Agent SDK, OpenAI Codex SDK, Cursor SDK и фреймворк `pi`. Поэтому встроенная панель агента работает с разными провайдерами.
- **MCP-сервер.** Отдельный нативный бинарник `mcp-server-windows-x64.exe`. С клиентом он общается через stdio, с запущенным приложением — через локальный сокет или named pipe. В Claude Code подключается командой `… --app desktop --agent claudeCodeCLI`.
- **Дизайн-киты** в комплекте, в виде `.pen`-файлов: shadcn, HeroUI, Halo, Lunaris, Nitro.

### Формат `.pen`

- JSON, текущая версия схемы — `2.21`. Схема опубликована: <https://docs.pencil.dev/for-developers/the-pen-format>. Наша спецификация — [05-pen-format](05-pen-format.md).
- **На диске не зашифрован.** MCP-сервер pen.dev по-прежнему пишет агентам: «.pen files are encrypted: access them only via the MCP tools», то же повторяют обзоры начала 2026 года. Но все реальные файлы, которые мы смотрели, — обычный JSON в UTF-8 (`{"version": "2.21", "children": [...]}`). Файлы пользователя относятся к версиям 2.6, 2.17, 2.18 и 2.21. Совместимость через публичную схему вполне достижима.

### Работа с агентом — чему стоит поучиться

Набор MCP-инструментов намеренно минимален:

| Инструмент | Назначение |
|---|---|
| `get_app_state` | Активный документ, выделение, состояние аккаунта, подсказка, с чего начать |
| `read_skill` | Отдаёт дизайн-скилл: SKILL.md и гайды, на которые он ссылается |
| `get_style` | ~26 стилевых архетипов с настраиваемыми шрифтами, цветами и изображениями |
| `execute` | Выполняет небольшой JavaScript-сниппет над документом |
| `browser` | Живая веб-страница во встроенном браузере: импорт DOM в редактируемые слои, скриншот, CDP |

Ключевые идеи `execute` (по публичной документации скилла):

- **Один сниппет — одна транзакция.** Если любая строка падает, откатываются все изменения.
- **Патч вместо повторной отправки.** Упавший вызов возвращает `editId`, и агент присылает только `edits` — пары `find`/`replace` к упавшему сниппету. На длинных сниппетах это заметно экономит токены.
- **Маленький словарь:** `Insert`, `Copy`, `Update`, `Replace`, `Move`, `Delete`, `SetVariables`, `GetVariables`, `Get`, `FindEmptySpace`, `Print`, `TakeScreenshot`, `Export`, `Generate`.
- **Чтение через visitor с диагностикой раскладки.** `Get(root, (node, ctx) => …)` возвращает `ctx.bounds` (рассчитанную раскладку) и `ctx.problems` (`"partially clipped"` / `"fully clipped"`). Агент проверяет структуру без скриншота.
- **Карта «имя → id»** после каждого вызова: в следующих вызовах можно ссылаться на только что созданное.
- **Глобальные переменные сохраняются.** Присваивания без `const` / `let` живут между вызовами.
- **`placeholder: true`** помечает фреймы в работе, интерфейс показывает их как незавершённые.
- **Скриншоты явные и приходят в том же вызове** (`TakeScreenshot([id])`): секция собирается и проверяется за один заход.

Скилл учит не только API, но и вкусу:
- держать корень документа чистым;
- повторяющиеся элементы сначала оформлять как компоненты;
- проверять каждую секцию сразу;
- не рисовать логотипы из path;
- не заворачивать всё в карточки;
- не злоупотреблять градиентами и тенями;
- никогда не угадывать размеры текста.

### Цены (примерно с 15 октября 2026)

| | Free | Pro | Ultra |
|---|---|---|---|
| Цена | $0 | $16 за пользователя в месяц (при оплате за год) | $48 за пользователя в месяц (при оплате за год) |

Редактор, локальные файлы, компоненты, переменные, импорт и экспорт бесплатны на любом плане. Ограничение, которое имеет значение: **засчитывается любой день, когда агент работал в pen.dev, — включая внешнего агента через MCP на собственной подписке пользователя.**

### Сильные и слабые стороны

- ➕ Отличная эргономика для агента, сильный дизайн-скилл, стилевые архетипы, импорт живых страниц, файлы в git.
- ➖ Закрытый код, теперь с лимитами. Нет полноценного совместного редактирования. Большие файлы тормозят. Сгенерированный код не совпадает с дизайном один в один.

## 2. OpenPencil (open-pencil/open-pencil)

- **Проект.** <https://github.com/open-pencil/open-pencil> · <https://openpencil.dev> · MIT (облачный пакет — Apache-2.0). Создан 2026-02-27, v0.16.0 вышла 2026-10-14, около 9.1k звёзд. Основной автор — Данила Поярков (`dannote`), ~90% коммитов. Установлен локально (v0.16.0).
- **Стек:**
  - интерфейс — Vue 3, Reka UI, Tailwind 4;
  - десктоп — Tauri v2 (~15 МБ), либо PWA;
  - рендер — Skia через CanvasKit WASM поверх WebGL;
  - раскладка — форк Yoga WASM с CSS Grid;
  - `.fig` — Kiwi + Zstd;
  - P2P-совместная работа — Yjs + WebRTC (Trystero);
  - ИИ — Vercel AI SDK с собственным ключом пользователя;
  - монорепозиторий на Bun.
- **Пакеты на npm** (0.16.0, MIT): `@open-pencil/core` с подпутями `editor`, `canvas`, `canvaskit`, `layout`, `tools`, `design-jsx`, `io`, `io/formats/*`, `lint`, `xpath`, `rpc`, `figma-api` и др.; а также `scene-graph`, `pen`, `fig`, `kiwi`, `design-jsx`, `dom-css`, `emit`, `vue`, `mcp`, `cli`.
- **Интерфейс для агента:**
  - больше 100 мелких MCP-инструментов: создание, изменение, раскладка, булевы операции, пути, переменные, компоненты;
  - JSX: `render` / `get_jsx`;
  - диффы `diff_*`, включая визуальный;
  - `lint` / `lint_fix`, `analyze_colors|typography|spacing|clusters|overlaps`, `design_to_tokens`;
  - `eval` с API, совместимым с плагинами Figma.

  Десктоп-приложение открывает RPC на `127.0.0.1:7600`, MCP по HTTP на `/mcp` и WebSocket-мост на `:7601`. Есть также режимы stdio и headless.
- **Пробелы:** нет прототипирования; маски, grid-раскладка и управление стилями реализованы частично; RTL неполный; API нестабилен (0.x); bus factor ≈ 1.

### Практические тесты (2026-10-20, Bun 1.3.14, Windows 11)

**Импорт `.pen` через `@open-pencil/pen`.** Пакет умеет только читать: `parsePenFile(json) → SceneGraph`. **Записи нет.** Результаты на реальных файлах пользователя:

| Файл | Версия | Результат |
|---|---|---|
| `eval/design.pen` (335 КБ) | 2.17 | Разобран за 46 мс. 184 фрейма, 134 текста, 360 ref → инстансы. |
| `negolosom/app.pen` (802 КБ) | 2.21 | Разобран за 1.4 с; после разворачивания инстансов получилось ~39k нод сцены. |
| `negolosom/website.pen` | 2.18 | Разобран за 19 мс. |
| `b2bzakup-ru/main.pen` | ? | **Ошибка:** `Object.values requires that input parameter not be null` |

Поддержанные типы: `frame`, `rectangle`, `ellipse`, `text`, `path`, `ref`; иконки превращаются в текстовые глифы. **Не поддержаны:** `polygon`, `note`, `prompt`, `context`, `script`, `browser`, а также заливки `shader` и `mesh_gradient`.

**Рендер без UI через `@open-pencil/core/io/formats/raster`.**

- Под Bun на Windows заработал **после исправления бага**. `headless.ts` строит путь к CanvasKit через `new URL('.', …).pathname`, и на Windows получается `/C:/…`. Замена на `fileURLToPath` решает проблему — это стоит отправить PR в OpenPencil.
- Фрейм 1180×760 отрисовался за 4–6 с при холодном старте: инициализация CanvasKit и загрузка шрифтов. Повторные рендеры должны быть намного быстрее — измерим в фазе 1.
- Качество на реальном макете хорошее: кириллица, переменные, компоненты и раскладка верные.
- Два дефекта на этом макете:
  - заливки-шейдеры рендерятся **чёрными**;
  - у состояний компонентов пропали заливки — вероятно, неверно разрешаются переменные, зависящие от темы.

Оба дефекта — задачи для `pen-bridge` и его тестов.

## 3. Тоже важно: ZSeven-W/openpencil

- **Проект:** <https://github.com/ZSeven-W/openpencil> — другой проект с тем же именем. MIT, ~6.3k звёзд, создан 2026-02-17, активно развивается.
- **Устройство:**
  - **ядро на Rust**, рендер в WASM, один нативный бинарник без браузерного движка;
  - собственный JSON-формат `.op`, UI-киты `.pen` только импортируются;
  - MCP-сервер, CLI `op`, «Concurrent Agent Teams», экспорт кода во множество фреймворков.
- **Что из этого следует.** Холст для агента с ядром на Rust вполне реален, но это отдельный движок и отдельный формат, поэтому строиться на нём мы не будем — см. [ADR-005](../adr/ru/005-stack-bun-tauri-rust.md). К его библиотеке стилей и экспорту в разные фреймворки стоит вернуться в фазе 3.

## 4. Итог

| Берём | Откуда | Зачем |
|---|---|---|
| Рендер, раскладка, scene graph, `.fig`, экспорт, линт, анализ | Пакеты OpenPencil | Бесплатный движок уровня Figma; мы только исправляем и контрибьютим |
| `.pen` как родной формат | Публичная схема pen.dev | Существующие файлы продолжают работать; чистые git-диффы |
| `execute`: транзакционные сниппеты, патч при ошибке, диагностика через visitor, карта имён | Идея pen.dev, наша реализация | Лучшая известная эргономика для агента |
| Скилл и стилевые архетипы | Идея pen.dev, наши тексты | Хороший дизайн по умолчанию |
| Свой агент без учёта использования | — | Ради этого проект и затевается |

## 5. Найденные риски

| Риск | Как снижаем |
|---|---|
| `@open-pencil/pen` только читает и теряет данные | Свои пакеты `pen-format` и `pen-bridge`; источник правды — исходное дерево `.pen` (см. [04-architecture](04-architecture.md)) |
| Нестабильный API OpenPencil (0.x) | Фиксируем точные версии; все вызовы движка изолированы за адаптерами `pen-bridge` и `engine` |
| pen.dev меняет схему `.pen` | Миграции по версиям; неизвестные свойства сохраняются |
| Баги Windows в headless-режиме | PR в OpenPencil; до слияния — локальный патч через `patch-package` / `bun patch` |
| Подписка Claude внутри стороннего приложения | Никогда не встраиваем OAuth; запускаем собственный `claude` CLI пользователя ([ADR-004](../adr/ru/004-agent-connection.md)) |
