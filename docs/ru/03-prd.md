# 03 · Требования к продукту

[English](../en/03-prd.md) · **Русский**

## Персоны

| Персона | Контекст | Что нужно |
|---|---|---|
| **Разработчик, работающий через агента** (основная) | Делает приложения с Claude Code; хочет сначала увидеть интерфейс, а потом писать код | Агент проектирует в файле рядом с кодом; скриншоты прямо в чате; никаких лимитов |
| **Беженец из pen.dev** | Десятки `.pen`-файлов; бесплатный план теперь ограничивает агента | Открывать, править и сохранять старые файлы; привычный процесс работы с агентом |
| **Дизайнер, который правит руками** (фаза 2) | Дорабатывает то, что сделал агент | Настоящий холст: выделить, перетащить, поправить текст, сменить цвет, отменить |
| **Автор инструментов / CI** | Хочет проверять дизайн в пайплайнах | Рендер без UI, линт, экспорт; стабильный CLI |

## Ключевые сценарии

1. **Экран по описанию.** В Claude Code: «Сделай экран онбординга в `design/app.pen`».
   - Агент читает скилл и берёт стилевой архетип или токены проекта.
   - Собирает экран за несколько вызовов `execute`, прикладывает скриншоты и исправляет проблемы.
   - Файл сохраняется. Пользователь видит результат на скриншоте в чате (фаза 1) или вживую на холсте (фаза 2).
2. **Доработка существующего файла pen.dev.** «Сделай карточки тарифов плотнее и добавь переключатель годовой оплаты». Агент читает нужное поддерево, правит инстансы через `descendants` и проверяет результат. Файл по-прежнему открывается в pen.dev.
3. **Дизайн → код.** «Реализуй экран Settings в нашем приложении на Next.js». Агент читает компоненты и переменные, сопоставляет токены с CSS проекта и сравнивает результат с рендером.
4. **Код → дизайн.** «Воссоздай наши компоненты `Button` и `Card` в дизайн-файле». Токены из `globals.css` становятся переменными `.pen`, компоненты — фреймами с `reusable`.
5. **Варианты.** «Дай три направления для hero-блока». Три фрейма-заготовки рядом, каждый собран и снят на скриншот. В фазе 3 их параллельно делают субагенты.
6. **Проверка в CI.** `tusche render design/app.pen --out shots/` и `tusche lint design/app.pen` в GitHub Actions.

## Требования — фаза 1 (MVP, «компаньон»)

### Функциональные

| ID | Требование | Приоритет |
|---|---|---|
| F1 | Открывать `.pen` версий 2.x (минимум 2.6–2.21); неизвестные свойства сохраняются | Must |
| F2 | Сохранять `.pen` как каноничный JSON: стабильный порядок ключей, отступ 2 пробела, LF, перевод строки в конце | Must |
| F3 | MCP-сервер по stdio с инструментами `get_app_state`, `read_skill`, `get_style`, `execute`, `open_document`, `save_document` | Must |
| F4 | API `execute` по [06-agent-api](06-agent-api.md): транзакции, повтор через `edits`/`editId`, карта имён, предупреждения | Must |
| F5 | Visitor в `Get` с `ctx.bounds` и `ctx.problems`, рассчитанными движком раскладки OpenPencil | Must |
| F6 | `TakeScreenshot` возвращает PNG прямо в ответе MCP | Must |
| F7 | `Export` в PNG / JPEG / WEBP / PDF / SVG; HTML + Tailwind — желательно | Should |
| F8 | Компоненты: `reusable`, `ref`, переопределения через `descendants` (свойства и замена), слоты | Must |
| F9 | Переменные и темы: ссылки `$name`, значения по темам, `SetVariables` / `GetVariables` | Must |
| F10 | Иконки (сначала lucide, затем Material Symbols и phosphor) отрисовываются векторами | Should |
| F11 | Собственный скилл (SKILL.md и гайды), который отдаёт `read_skill` | Must |
| F12 | Не меньше 8 стилевых архетипов через `get_style` | Should |
| F13 | CLI без UI: `tusche render`, `tusche exec`, `tusche lint`, `tusche mcp` | Must |
| F14 | Живой предпросмотр: локальная веб-страница, которая перерисовывает открытый документ при каждом изменении | Should |
| F15 | Прокси к некоторым инструментам анализа OpenPencil (`lint`, `analyze_*`) | Could |

### Нефункциональные

| ID | Требование |
|---|---|
| N1 | «Тёплый» `execute` без скриншота: < 300 мс на документе из 1 000 нод |
| N2 | «Тёплый» скриншот фрейма 1440×1024: < 1.5 с |
| N3 | Круговая конвертация `.pen` → Tusche → `.pen` без правок даёт побайтно тот же файл после канонизации |
| N4 | Работает на Windows, macOS и Linux с Bun ≥ 1.3 или Node ≥ 22 |
| N5 | Песочница не имеет доступа к файловой системе и сети, кроме как через функции API |
| N6 | Во время работы в сеть ходим только за шрифтами и иконками; они кэшируются, загрузку можно отключить |

## Требования — фаза 2 (десктоп)

- Приложение на Tauri поверх `@open-pencil/vue` и `@open-pencil/core/editor`; `.pen` открывается и сохраняется нативно.
- Ручное редактирование: выделение, перемещение, изменение размера, правка текста, заливки, панель раскладки, панель слоёв. Undo/redo общий с агентом.
- Панель агента запускает установленный у пользователя `claude` CLI (или Codex / Gemini CLI) с уже настроенным MCP Tusche.
- Ноды prompt / note / context на холсте, как в pen.dev.
- Живой курсор агента; фреймы с `placeholder` показываются как «в работе».
- Импорт из браузера: загрузить URL и превратить DOM в слои (через HTML-импорт OpenPencil).

## Требования — фаза 3

- Параллельные агенты (разделение работы или несколько вариантов) через субагентов CLI пользователя.
- Библиотеки компонентов между файлами (`imports`).
- Двусторонняя синхронизация дизайн-токенов с CSS / Tailwind.
- Опционально — генерация изображений и SVG через собственные MCP-серверы пользователя.

## Вне рамок

Прототипирование и анимация, серверы совместной работы, хостинг моделей, маркетплейс плагинов, сохранение в `.fig`, попиксельное совпадение с рендером pen.dev.

## Метрики успеха

- Все 6 ключевых сценариев проходят от начала до конца на реальных файлах мейнтейнеров.
- 100% существующих `.pen`-файлов пользователя открываются; ≥ 95% рендерятся без видимых дефектов.
- В среднем агент тратит на готовый экран не больше токенов, чем в pen.dev на тот же запрос. Замеряется на наборе эталонных задач.
