# 01 · Видение

[English](../en/01-vision.md) · **Русский**

## В одном предложении

Tusche — бесплатный открытый дизайн-холст: проектирует **ваш** агент, а вы наблюдаете, направляете и правите, и файлы при этом лежат рядом с кодом.

## Проблема

ИИ-агенты научились неплохо собирать интерфейсы, но код плохо подходит для *поиска* дизайна. В нём не сравнишь пять вариантов рядом, не перетащишь карточку и не окинешь взглядом светлую и тёмную темы сразу. Холсты для агентов решили эту задачу: агент пишет прямо на холст и делает скриншоты. Самый известный из них — pen.dev.

В октябре 2026 года pen.dev ввёл платные планы. На бесплатном агент может работать в приложении только **5 дней в месяц**. В этот лимит попадает и работа внешнего агента через MCP, например Claude Code, даже если пользователь отдельно платит за агента. Сам редактор остался бесплатным, а *цикл работы с агентом* — то, ради чего pen.dev и выбирают, — нет.

OpenPencil (MIT) — мощная бесплатная альтернатива: движок уровня Figma и больше 100 MCP-инструментов. Но интерфейс для агента у него широкий и низкоуровневый, а `.pen` он умеет только импортировать.

## Что такое Tusche

1. **Холст для агента в первую очередь.** Главный пользователь API — LLM-агент, а не человек с мышкой. API экономит токены, безопасен благодаря транзакциям и даёт агенту проверять собственную работу.
2. **Движок OpenPencil, но не форк.** Используем опубликованные пакеты `@open-pencil/*`, а исправления отправляем в основной репозиторий.
3. **`.pen` — родной формат.** Основа — открытая опубликованная JSON-схема `.pen`. Существующие документы pen.dev открываются, редактируются и сохраняются без конвертации.
4. **Свой агент.** Claude Code, Codex, Gemini CLI, OpenCode или любой MCP-клиент. Tusche не нужны ни свой API-ключ, ни аккаунт, и он никак не ограничивает использование агента.
5. **Всё локально.** Файлы на диске, без облака и по умолчанию без телеметрии.

## Принципы

| Принцип | Что это значит на практике |
|---|---|
| Сначала агент | Один транзакционный `execute` лучше сотни мелких инструментов. Ошибки исправляются патчем, без повторной отправки. Каждый ответ компактный. |
| Проверяй, а не угадывай | Агенту доступны дешёвые структурные проверки (границы, обрезка содержимого) и скриншоты по запросу. |
| Открытый формат | `.pen` остаётся простым, каноничным JSON с удобными диффами. Неизвестные свойства переживают круговую конвертацию. |
| Без лимитов | Никакого учёта использования, платных функций и кредитов на модели. |
| Тонкий слой | Всё, что делает движок, берём из OpenPencil. Свои — только агентный слой, мост к `.pen` и UX. |
| «Чистая комната» | Поддержка `.pen` написана только по публичной документации: ни кода, ни ассетов, ни текстов скиллов pen.dev. |

## Чего мы не делаем

- Не заменяем Figma для больших дизайн-команд: прототипирование, ветки, корпоративные библиотеки.
- Не пишем свой движок рендера или раскладки. См. [ADR-001](../adr/ru/001-build-on-openpencil.md) и [ADR-005](../adr/ru/005-stack-bun-tauri-rust.md).
- Не хостим модели, не продаём кредиты и не строим облачный сервис.
- Не добиваемся попиксельного совпадения с рендером pen.dev. Совместимость нужна на уровне *формата файла* и *работы агента*.
- Не делаем совместное редактирование в реальном времени в фазах 0–2. Позже можно подключить слой Yjs из OpenPencil.

## Для кого

- **Разработчики, работающие с агентами**, которым нужно исследовать дизайн визуально до кода или параллельно с ним.
- **Бывшие пользователи pen.dev** с папкой `.pen`-файлов, которые хотят работать дальше без лимитов.
- **Авторы инструментов**, которым нужен скриптуемый дизайн-движок без UI для CI: рендер, линт, экспорт.

## Как выглядит успех

- Claude Code через Tusche проектирует многоэкранное мобильное приложение в `.pen`-файле и проверяет его по скриншотам, а pen.dev открывает этот же файл.
- Дизайнер открывает файл в десктопном Tusche, правит руками, и агент подхватывает изменения.
- CLI без UI рендерит файл в CI и роняет сборку при ошибках линта.
